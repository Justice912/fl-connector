## ⚠️ Gotcha: "the app is old / no bridge" = stale Vercel deploy

- The frontend is linked to a **Vercel deployment** (`frontend/.vercel/project.json`, project "frontend"). Opening that hosted URL shows a **stale static build** — local commits never reach it until rebuilt+redeployed.
- This is a **local FL Studio tool**: a hosted HTTPS page can't reliably reach the local `http://127.0.0.1:8765` backend (mixed content). **Run it locally instead.**
- Phase 3 changes are **backend-only** — they never *look* different in the UI; you hear them in the generated MIDI after Generate → Approve → apply in FL.

## How to run locally

```powershell
# Backend (:8765)
cd "C:\Users\HP\Vocals APP\fl-connector\backend"
.\.venv\Scripts\python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765

# Frontend (:5173) — Vite proxies /api to the backend
cd "C:\Users\HP\Vocals APP\fl-connector\frontend"
npm run dev -- --host 127.0.0.1 --port 5173
```

Then open **http://127.0.0.1:5173**. Health check: `GET http://127.0.0.1:8765/api/health` → `{"ok":true,...}`. Song generate: `POST /api/songs/generate` with `{prompt,genre,bpm,key,scale,bars}`.

**Bridge:** to connect, FL Studio must be open with loopMIDI ports + Flapi controller scripts running; then refresh the bridge panel. "disconnected" just means FL/Flapi wasn't live at probe time.
